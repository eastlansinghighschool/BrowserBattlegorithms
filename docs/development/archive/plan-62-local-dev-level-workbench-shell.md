## Packet Summary

Goal: Add a local-development-only browser workbench shell that lets an admin/developer select a guided level, inspect its normalized context and readiness checks, and copy the deterministic agent repair prompt generated by Plan 61.

Why this packet exists:

The readiness engine and prompt renderer are useful from the CLI, but the eventual workflow is visual: inspect the level, see the relevant contracts, and hand a precise prompt to an implementation agent. This packet creates the read-only browser surface without adding editor or filesystem-write risk.

Non-goals:

- Do not add Blockly editing.
- Do not run scratch solutions from the browser yet; that is Plan 63/64 territory.
- Do not save or mutate files.
- Do not redesign the student guided campaign UI.
- Do not expose this surface in production deployment.
- Do not add authentication or server features.

## Implementation Requirements

### Requirement 1: Dev-Only Access

Required behavior:

- The workbench must be available in local development.
- It must not be linked or reachable from the student-facing production UI unless the current architecture already permits local-only pages in a safe way.
- Production build behavior must be preserved.

Constraints:

- Do not add login/auth.
- Do not add a server dependency beyond existing Vite dev behavior.
- If production exclusion is ambiguous, stop for owner review.

### Requirement 2: Read-Only Level Context

Required behavior:

- Selecting a level updates all displayed context without mutating app gameplay state.
- Show repository-relative paths.
- Show readiness checks grouped by status.
- Show concept matrix data in a compact, scannable form.
- Show project metadata and project fixture status when applicable.

Constraints:

- Avoid a decorative dashboard. This is a dense developer tool.
- Text must fit on laptop and narrow desktop widths.

### Requirement 3: Prompt Display

Required behavior:

- Display the Plan 61 generated prompt in a textarea or code block.
- Provide a copy button if straightforward.
- The prompt output should match CLI output for the same level.

Constraints:

- Do not let UI code generate a separate prompt template.
- Consume the shared renderer.

### Requirement 4: No Mutation

Required behavior:

- The workbench must not write files.
- The workbench must not alter guided progress or project workspace storage.
- The workbench must not call `startLevel` or enter normal gameplay modes unless strictly isolated in a test-safe preview not authorized by this packet.
